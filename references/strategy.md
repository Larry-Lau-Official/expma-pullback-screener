# EXPMA 回踩策略说明

> **免责声明**：本文档仅用于技术形态学习与研究，不构成投资建议或买卖依据。行情数据来自第三方，禁止分发或泄露；据此操作风险自负。

## 一、形态定义

目标形态来自东方财富个股日 K 线的典型走势，分四个阶段：

1. **底部蓄势**：股价在低位横盘或缓慢震荡，EMA1 与 EMA2 纠缠走平
2. **放量拉升**：股价突破，EMA1 上穿 EMA2 并形成多头排列，期间出现一次或多次涨停，成交量显著放大
3. **缩量回调**：股价见阶段高点后回落，回调周期通常不超过 10 个交易日，成交量萎缩
4. **贴近 EMA2**：最新交易日收盘价回落至 EMA2（50 日指数移动平均线）附近，上下 1.5% 区间内——这只是技术形态观察点，不代表任何操作建议

本策略筛的是第 4 阶段"正在接近"的票，不是已经从 EMA2 反弹上涨的票。

## 二、EXPMA 指标

EXPMA（指数移动平均）参数为 12 日与 50 日，与东方财富 App 默认显示一致。已用三只真实个股校准，计算结果与截图数值完全吻合。

指数移动平均递推公式：

```
EMA_today = close_today × 2/(N+1) + EMA_yesterday × (1 - 2/(N+1))
```

首日 EMA 取首日收盘价。EMA1（12 日）为短期线，EMA2（50 日）为长期线。

## 三、条件细则

### 板块过滤

- 排除科创板：代码 688、689 开头
- 排除北交所：代码 8、43、83、87、92 开头
- 排除 ST、*ST、PT、退市股：名称关键词匹配（BaoStock 列表直接带标记）
- 排除指数与基金：按证券类型过滤
- 保留：沪深主板（000/001/002/003/600/601/603/605）、创业板（300/301）

### 市值与股价过滤（前置）

- 总市值 < 300 亿元（新浪列表 `mktcap` 字段，单位万元，阈值 3,000,000）
- 当前股价 < 50 元（新浪列表 `trade` 字段）
- 这两个条件在拉 K 线之前执行。A 股绝大部分个股本就在此范围内（4600 余只中约 3840 只符合），主要剔除的是少数大盘蓝筹与高价股
- 数据源：新浪 `Market_Center.getHQNodeData` 一次分页拉全市场，缓存按最新交易日判断（出现新交易日即刷新）
- 可通过 `--max-mktcap`（万元）与 `--max-price`（元）调整；缺失市值数据的股票保守保留

### 阶段高点与回调周期

在分析窗口（最近 150 个交易日）内找到最高价当天作为阶段高点。回调天数 = 最新交易日 - 高点日的交易日数。要求 1-10 个交易日；11-12 日放入备选池并扣分，超过 12 日直接排除。

### 上涨段

从高点向前 60 个交易日内找最低价当天作为起涨点。要求从起涨点到高点的涨幅 ≥ 20%。在起涨日到高点之间统计涨停次数：

- 主板：单日涨幅 ≥ 9.8%
- 创业板（300/301）：单日涨幅 ≥ 19.8%
- 至少 1 次涨停，为硬条件

### EMA2 回踩

判定对象是**数据源最新交易日的收盘价**：收盘价与当日 EMA2 的相对偏离在 ±1.5% 以内即为命中。附加 0.02 元价格精度缓冲（因 A 股最小变动单位为 0.01 元，而 EMA2 为浮点值）。

**盘中最低价不参与判定**。若当日最低价触及 EMA2、但收盘已反弹超出 ±1.5%，一律排除——这类票属于盘中回踩形态，不符合"当前贴近 EMA2"的口径。偏离超过 1.5% 的没有"接近中"备选，直接剔除。

## 四、评分排序

评分不影响是否入选，仅用于结果排序：

| 因子 | 加分规则 |
|------|----------|
| 涨停次数 | 每次 +8，最多计 5 次 |
| 阶段涨幅 | 涨幅% / 10，最多 +12 |
| EMA1 > EMA2 | +8（多头排列） |
| EMA2 向上 | +6（近 5 日 EMA2 上升） |
| 最新交易日收盘价贴近 EMA2 | +10（已通过硬条件） |
| 回调缩量 | 回调均量 < 上涨均量 × 0.8 时 +8 |
| 回调超期 | -12 |

## 五、调参建议

- **结果过多**：收紧 `--ema2-tol 0.01`、提高 `--min-rise 30`、要求 `--min-limit-ups 2`
- **结果过少**：放宽 `--ema2-tol 0.025`、降低 `--min-rise 15`、放宽 `--max-pullback 12`
- **短线视角**：缩短 `--max-pullback 7`
- **波段视角**：放宽 `--max-pullback 12`

## 六、数据源说明

### 主源：BaoStock（证券宝）

选它的原因：网页行情接口（东财、腾讯、新浪）对高频请求有严格风控，密集抓取会触发 WAF 拦截（501）或连接重置，导致选股无法稳定完成。BaoStock 是面向量化的服务端数据协议，免费、免注册、非爬虫，稳定性远好于网页接口。

- 依赖：`vendor/` 目录内已包含 baostock 0.9.4、pandas、numpy（离线可用，不污染系统 Python）
- 股票列表：`bs.query_all_stock(day)`，按证券类型与代码前缀过滤，自动排除科创板(688/689)、北交所、指数基金，并读取 ST 标记
- K 线：`bs.query_history_k_data_plus(..., frequency='d', adjustflag='2')`，前复权日线，含 pctChg 涨跌幅字段
- 更新节奏：交易日 17:30 后入库当天日线，18:00 完成复权因子。盘中运行拿到的是上一交易日数据
- 兼容性：BaoStock 0.9.4 的 `rs.next()` 在 Python 3.13 + 新 pandas 下对 K 线查询会死循环，本脚本直接读 `rs.data` 规避；列表查询的 `next()`+`get_row_data()` 正常

### 性能与稳定性保护

- 串行抓取（BaoStock 单连接协议，不适合并发）
- 每 300 只重新登录，避免长连接超时
- 每 1000 只落盘一次结果，中断后重跑可续传
- 本地缓存：`output/.cache/bs_<代码>.json`，按最新交易日判断新鲜度（数据末日落后即重拉，停牌股在新交易日后抓过则跳过）；`--no-cache` 强制刷新
- 全市场约 4600 只，单只约 0.3 秒，首次约 20-25 分钟，之后走缓存仅需数秒

### 备源：网页接口

`--source web` 启用。新浪财经 `Market_Center.getHQNodeData` 拉列表，东财 `push2his` / 腾讯 `web.ifzq.gtimg.cn` 拉前复权 K 线。内置全局限速（0.12s 间隔）与指数退避，但这些接口本身无官方保障，触发风控后需等待较长时间恢复，仅在 BaoStock 不可用时作为临时替代。

### 关于爬虫方式

网页爬虫（模拟浏览器抓东方财富页面）理论上可行，但不推荐：反爬机制强、页面结构一变就失效、维护成本高，且有合规风险。BaoStock 这类提供稳定数据接口的免费方案是更优解。若需要更高的实时性和数据维度，可考虑低价付费服务（如 Tushare Pro 积分制、AllTick 等），但对日线级选股场景并非必需。

## 七、风险提示

本工具仅为技术形态筛选，不构成投资建议。选出的个股还需结合基本面、消息面、市场环境综合判断。涨停后回调的个股波动较大，注意控制仓位与风险。
